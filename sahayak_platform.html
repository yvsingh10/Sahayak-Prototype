SAHAYAK System Architecture & Engineering Alignment

Deconstruction of prototype implementation according to PBL Course Rubric

1. Decoupled Data Access Layer (Repository Pattern)

All database mutations occur through an abstract SahayakRepository class persisting to Chrome's window.localStorage. The presentation layer never touches raw storage keys, allowing an effortless swap to REST/GraphQL APIs.

2. Strict 48-Hour SLA Gateway & Auto-Escalation

Every submitted ticket starts a non-pausable 48-hour countdown timer. If a desk officer does not triage the ticket within 48 hours, or if community upvotes propel P(t) ≥ 100, the ticket state machine transitions to ESCALATED and triggers alert dispatches to the Nodal Municipal Commissioner.

3. Dynamic Mathematical Priority Algorithm

Mathematical index:
P(t) = W_base + 10 * log2(1 + U) + 5 * (hours_elapsed / 24) Where W_base ∈ {20, 40, 60}, U is unique verified citizen endorsements, and time elapsed incrementally escalates older neglected complaints.

4. Two-Factor Photographic Verification & Closure

A ticket cannot be closed unilaterally by the department. The field team must upload an "After Repair" photo proof to transition to WORK_COMPLETED. Final closure requires verification from the original complainant citizen.
